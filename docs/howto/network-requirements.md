# ネットワーク要件と対策

> 確認日: 2026年11月3日（皇紀2686年・令和8年）／ 信頼度: ✅公式確認 ・🔶二次情報 ・⚪一般的知見（出典未検証）・⚠️未確認

## 1. 基本方針
帯域・ポート・許可ドメインは**ツールごとに異なり、変更される**。ここでは確認できた範囲と一般的な考え方を示す。数値は必ず各社の公式文書で確認すること。

## 2. 確認できた数値
| 項目 | 内容 | 信頼度 |
|---|---|---|
| Zoom 1080p の帯域 | 受信 1.8〜2.5Mbps、送信 3.0Mbps 前後など資料間で不一致。Zoom は自動最適化 | 🔶 |
| Jitsi（自前サーバ） | 3人目で不具合なら UDP 10000 を確認 | ✅ |
| Teams 会議の最大時間 | 30 時間 | ✅ |
| 公式の網羅的ポート表 | ⚠️ 今回は取得できていない | ⚠️ |

## 3. 一般的な考え方 ⚪
- **有線LANまたは Wi-Fi 5GHz/6GHz** を優先。2.4GHz は混雑しやすい。
- 会議中に大容量のアップロード／クラウド同期を止める。
- VPN 経由は遅延と帯域低下の原因。会議トラフィックを VPN から除外できるか管理者に確認（スプリットトンネル）。
- 企業ファイアウォールでは UDP が遮断されると TCP/TLS フォールバックで品質が落ちる。管理者が各社の公式一覧に従って許可する。
- プロキシ環境では WebRTC がうまく動かないことがある。

## 4. モバイル回線 ⚪
- 通信量を節約するには、映像オフ・受信画質低下・音声のみ参加。
- 移動中は切断に備え、再参加用のリンクと会議ID・パスコードを控える。

## 5. 診断手順 ⚪
1. 速度ではなく**遅延とパケットロス**を見る（上り帯域が不足しやすい）。
2. ツール内のネットワーク統計（接続品質表示）を確認。
3. 別回線（テザリング）で再現するか確認して切り分け。
